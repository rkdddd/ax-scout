## 알려진 한계와 남은 일

1. **자동 수집 예약 실행 미등록** — GitHub 비공개 저장소 생성, Secrets 등록, 첫 수동 실행 확인 (PLAN 16번, 계정 작업).
2. **Vercel 배포 전** — 배포 후 환경변수(`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`)를 Vercel에 따로 입력해야 한다 (PLAN 20번).
3. **로그인이 없다** — 배포 주소를 아는 사람은 누구나 보고 바꿀 수 있다. 연습용(가짜) 데이터만 쓰기로 한 이유다.
4. **없는 번호의 상세 화면은 안내 문구는 나오지만 응답 코드는 404가 아니라 200** — 데이터를 실시간으로 불러오는 구조 때문. 사람이 쓰는 데는 영향이 없다.
5. **링크 등록의 "내부 주소로 이동시키는 공개 주소"는 실제 재현으로 확인하지 못했다** — 이동 때마다 첫 연결과 같은 검사를 거치는 구조이고, 직접 입력한 내부 주소·내 컴퓨터를 가리키는 공개 이름은 모두 차단됨을 확인했다.
6. **검색 알림 후보 수집은 실제 Google 알림 주소로 시험하지 못했다** — 샘플 피드로 해석만 확인. 주소를 `.env`의 `GOOGLE_ALERT_RSS_URLS`에 넣으면 시험할 수 있다.
7. **개발 도구의 취약점 경고 21건(보통 19, 낮음 2)** — 모두 개발·빌드용 도구(eslint, shadcn 등)이며 강제 업데이트(`npm audit fix --force`)는 오히려 위험해서 하지 않았다.
